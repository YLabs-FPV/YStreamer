Усі виходи можуть працювати одночасно, у розділі **Streaming**. Кожен передає
те саме відео H.264, без звуку.

З окулярами DJI це відео наживо, яке приймають окуляри, передане далі як є:
та сама картинка, що й в окулярах, а не якісніший бортовий запис повітряного
модуля. Див. [запис](/docs/using/recording).

| Вихід | Напрямок                         | Для чого                                                 |
| ----- | -------------------------------- | -------------------------------------------------------- |
| RTSP  | Плеєри підключаються до пристрою | VLC, OBS, більшість плеєрів. Увімкнено за замовчуванням. |
| SRT   | В обидва боки                    | OBS через Wi-Fi чи інтернет: витримує втрати             |
| RTMP  | Пристрій надсилає                | YouTube, Twitch, Facebook, RTMP-сервери                  |
| UDP   | Пристрій надсилає                | QGroundControl, Mission Planner, multicast               |

Покрокові інструкції — для [VLC](/docs/other-software/vlc),
[OBS](/docs/other-software/obs),
[наземних станцій](/docs/other-software/ground-stations) і
[стрімінгових платформ](/docs/other-software/live-platforms).

## RTSP

Сервер, до якого підключаються плеєри. Картка показує адресу для
підключення з кнопкою **Copy**:

```
rtsp://ystreamer.local:554/stream
```

554 — стандартний порт RTSP, тож більшість плеєрів приймає адресу і без нього:
`rtsp://ystreamer.local/stream`.

| Налаштування     | Що робить                                                                |
| ---------------- | ------------------------------------------------------------------------ |
| Port             | За замовчуванням 554, стандартний порт RTSP. 554 або від 1024 до 65535.  |
| Path             | За замовчуванням `/stream`.                                              |
| TCP only         | Більша затримка, але працює через Wi-Fi з втратами та через брандмауери. |
| Require password | Ім'я користувача й пароль для плеєрів. Передаються без шифрування.       |

## SRT

SRT передає MPEG-TS і відновлює втрачені пакети, тож стабільно працює через
Wi-Fi та інтернет.

- **Listener** (за замовчуванням): пристрій чекає на порту, а приймачі
  підключаються до `srt://ystreamer.local:9000`.
- **Caller**: пристрій сам підключається до приймача за адресою
  **Receiver address** і **Port**. Так можна дістатися до OBS чи сервера в
  іншому місці. Деякі сервери також вимагають **Stream ID**.

| Налаштування | Що робить                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------ |
| Latency (ms) | Скільки чекати на втрачені пакети. 200 у локальній мережі, від 500 до 2000 через інтернет. |
| Passphrase   | Шифрує потік: від 10 до 79 символів, порожньо — без шифрування. Приймачу потрібна та сама. |

Картка показує, чи підключено приймач.

## RTMP

Надсилає відео на стрімінгову платформу або RTMP-сервер.

1. Обери **Service**: YouTube, Twitch, Facebook або **Custom server**.
2. Для власного сервера введи його **Server URL** (`rtmp://` або `rtmps://`,
   без ключа).
3. Встав **Stream key** з платформи.
4. Увімкни **RTMP** і натисни **Save**.

**Silent audio track** (увімкнено за замовчуванням) додає беззвучну доріжку:
деякі платформи відхиляють або позначають потоки без звуку.

До сервера, який не відповідає, пристрій підключається знову й знову. Коли
з'єднання є, картка показує **Live** з тривалістю та бітрейтом.

Див. [стрімінгові платформи](/docs/other-software/live-platforms).

## UDP

Надсилає відео на фіксовані приймачі, без встановлення з'єднання.

- **Format**: **RTP** (H.264 через RTP), який очікують QGroundControl і
  Mission Planner, зазвичай на порту 5600. **MPEG-TS** — для VLC, ffmpeg і OBS.
- **Destinations**: `хост:порт` кожного приймача, через кому, до 8. Адреси
  multicast теж працюють, наприклад `239.0.0.1:1234`.

<Admonition type="info">
  UDP не знає, чи хтось його приймає. Якщо нічого не з'являється, перевір адресу
  й порт приймача та його брандмауер.
</Admonition>

## Заставка в потоках

Поки відео немає, потоки передають [заставку](/docs/using/splash-and-logo),
тож плеєри лишаються підключеними й підхоплюють відео, коли воно повертається.
