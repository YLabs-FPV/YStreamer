YStreamer also runs on the **Radxa ROCK 3A**, a board built around the
Rockchip RK3568. It is **experimental**: the goggles link and the HDMI output
use the board's own USB controller and video hardware through the same code as
on the Pi, but far fewer people have run it there. The rest, the web
interface, streams, recordings and camera settings, works the same.

<Admonition type="info" title="What's different from the Pi">
  - **No ready-made image.** Install on Radxa's Debian 12 image with the
    install script.
  - **The goggles go into the upper USB 3 port**, with the board's OTG switch
    on DEVICE, not into a USB-C port.
  - **The board is powered through its own USB-C port**, which the goggles
    don't need.
  - **No Wi-Fi hot-spot** unless the board has a Wi-Fi module. Ethernet works
    as it does on the Pi.
  - **No [record button](/docs/using/record-button) and no reset pin**: the
    header's pins are numbered differently. Resetting by file still works:
    an empty `ystreamer-reset` file on the card's `config` partition, the one
    with `before.txt` on it.
  - **No "throttled" readings** on the Performance page; those come from the
    Pi's firmware.
</Admonition>

## What you need

- A **Radxa ROCK 3A** running Radxa's **Debian 12 (bookworm)** image: the
  latest release at [github.com/radxa-build/rock-3a](https://github.com/radxa-build/rock-3a/releases/latest),
  `rock-3a_bookworm_kde_r2` at the time of writing, which is the one this was
  developed against. It already carries the Rockchip video packages. The
  older Debian 11 (`b25`) images don't, and Radxa no longer publishes them
  for that release.
- A **USB-C power supply** with Power Delivery, 9 V or more and 18 W or more,
  into the board's USB-C port. Unlike the Pi's, that port is for power only
  here.
- The goggles cable: a **USB-C plug to USB-A socket OTG adapter** on the
  goggles, then a **USB-A to USB-A cable** from it to the board's **upper
  USB 3 port**, the one beside the OTG switch. The adapter always goes on the
  goggles' side.
- An HDMI cable and a screen, if you want the picture on one.

## Set the board up

1. Flash Radxa's image, boot the board and set it up (user, network, SSH) the
   way Radxa's instructions say.
2. Set the **OTG switch** beside the upper USB 3 port to **DEVICE**. In the
   HOST position the goggles see nothing at all. Leave the port's overlay in
   `rsetup` (Overlays) at its default, "controlled by hardware switch"; "Set
   OTG port to Peripheral mode" works too, "Host mode" doesn't.
3. Radxa's image starts a desktop, which keeps the HDMI output for itself.
   Boot to the console instead:

   ```sh
   sudo systemctl set-default multi-user.target
   sudo reboot
   ```

   `sudo systemctl set-default graphical.target` brings the desktop back.

## Install

The [install script](/docs/getting-started/install-script) recognises the
board. Over SSH:

```sh
curl -fsSL https://ystreamer.yarosfpv.com/install.sh | sudo sh
```

On the ROCK 3A it also:

- installs Radxa's video packages, `librockchip-mpp1` and
  `gstreamer1.0-rockchip1`, which decode and encode in hardware;
- switches off Radxa's own USB gadget services (`radxa-otgutils`: ADB and
  USB networking over the OTG port), if any are enabled, since they would
  take the port back every time the goggles connect;
- installs the package built for Debian 12. Updates from the web interface
  pick that package too.

Then open `http://<hostname>.local`, with the name you gave the board,
connect the goggles and switch them on. The **Logs** page shows "Link is
live", and HDMI shows the stream.

## If something's wrong

- **"no USB device controller" in the logs**: the OTG switch is on HOST, or
  an `rsetup` overlay forces host mode. Set the switch to DEVICE, put the
  overlay back, and reboot.
- **The goggles don't connect**: try another OTG adapter; some leave out the
  resistor that tells the goggles they're facing a host. Power the board
  first, then the goggles, then the air unit.
- **The stream works but HDMI shows nothing**: the desktop is still running
  (see above), or the Rockchip packages didn't install:
  `apt-cache policy gstreamer1.0-rockchip1` should show a version. The log
  line "decoding with mppvideodec" means the hardware decoder was found;
  "decoding with avdec_h264" means it wasn't, and the video is decoded in
  software.
- **Undoing it all**: `sudo apt remove ystreamer` prints how to switch Radxa's
  USB gadget services back on, and
  `sudo systemctl set-default graphical.target` brings the desktop back.
