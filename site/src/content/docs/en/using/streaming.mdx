All outputs can run at the same time, under **Streaming**. RTSP, SRT, RTMP and
UDP carry the same H.264 video, without sound. NDI and OMT carry it decoded,
for video mixers on the local network.

With DJI goggles, that's the live feed the goggles receive, passed on as it is:
the same picture as in the goggles, not the air unit's higher-quality onboard
recording. See [recording](/docs/using/recording).

| Output | Direction                     | Good for                                         |
| ------ | ----------------------------- | ------------------------------------------------ |
| RTSP   | Players connect to the device | VLC, OBS, most players. On by default.           |
| SRT    | Either way                    | OBS, over Wi-Fi or the internet: copes with loss |
| RTMP   | The device sends              | YouTube, Twitch, Facebook, RTMP servers          |
| UDP    | The device sends              | QGroundControl, Mission Planner, multicast       |
| NDI    | Mixers find the device        | vMix, OBS (DistroAV), TriCaster, on the LAN      |
| OMT    | Mixers find the device        | vMix, on the LAN. Open, nothing to install.      |

For step-by-step setups, see [VLC](/docs/other-software/vlc), [OBS](/docs/other-software/obs),
[NDI and OMT](/docs/other-software/ndi-and-omt),
[ground stations](/docs/other-software/ground-stations) and
[live platforms](/docs/other-software/live-platforms).

## RTSP

A server that players connect to. The card shows the address to use, with a
**Copy** button:

```
rtsp://ystreamer.local:554/stream
```

554 is RTSP's standard port, so most players also take it without one:
`rtsp://ystreamer.local/stream`.

| Setting          | What it does                                            |
| ---------------- | ------------------------------------------------------- |
| Port             | 554 by default, the standard RTSP port. 554, or 1024 to 65535. |
| Path             | `/stream` by default.                                   |
| TCP only         | More latency, but survives lossy Wi-Fi and firewalls.   |
| Require password | A user name and password for players. Sent unencrypted. |

## SRT

SRT sends MPEG-TS and recovers lost packets, so it holds up over Wi-Fi and
the internet.

- **Listener** (the default): the device waits on a port and receivers
  connect to `srt://ystreamer.local:9000`.
- **Caller**: the device connects to a receiver at **Receiver address** and
  **Port**. Use it to reach OBS or a server elsewhere. Some servers also want
  a **Stream ID**.

| Setting      | What it does                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------- |
| Latency (ms) | How long to wait for lost packets. 200 on a local network, 500 to 2000 over the internet.     |
| Passphrase   | Encrypts the stream: 10 to 79 characters, or empty for none. The receiver needs the same one. |

The card shows whether a receiver is connected.

## RTMP

Sends the video to a streaming platform or an RTMP server.

1. Pick the **Service**: YouTube, Twitch, Facebook, or **Custom server**.
2. For a custom server, enter its **Server URL** (`rtmp://` or `rtmps://`,
   without the key).
3. Paste the **Stream key** from the platform.
4. Turn **RTMP** on and **Save**.

**Silent audio track** (on by default) adds silent sound: some platforms
refuse or flag streams without audio.

A server that's down is tried again and again. The card shows **Live** with
the uptime and bitrate once it's through.

See [live platforms](/docs/other-software/live-platforms).

## UDP

Sends the video to fixed receivers, with no connection set up.

- **Format**: **RTP** (H.264 over RTP), what QGroundControl and Mission
  Planner expect, usually on port 5600. **MPEG-TS** for VLC, ffmpeg and OBS.
- **Destinations**: `host:port` of each receiver, separated by commas, up to 8. Multicast addresses work too, for example `239.0.0.1:1234`.

<Admonition type="info">
  UDP can't tell whether anyone receives it. If nothing shows up, check the
  receiver's address and port, and its firewall.
</Admonition>

## NDI and OMT

Both put a source on the local network that vMix, OBS and other mixers list by
themselves, as **HOSTNAME (YStreamer)**. Neither can carry the H.264 as it is,
so the device decodes the video and compresses each picture again, in
software. That only runs while a receiver is connected.

- **NDI** needs NDI's runtime on the device, which you install yourself: it's
  NDI's own software and doesn't come with YStreamer. Until it's there, the
  card says so and can't be turned on.
- **OMT** (Open Media Transport) is open and needs nothing extra.

| Setting      | What it does                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| Source name  | The name in the list of sources, after the device's hostname. `YStreamer` by default.                       |
| Picture size | Larger video is scaled down to this height: 480p to 1080p, 720p by default. Smaller video is left as it is. |
| Frame rate   | At most 30 (the default) or 60 frames per second.                                                           |

Each picture is compressed on its own, which takes far more bandwidth than
H.264. Connect the device and the mixer by Ethernet. The card shows how many
receivers are connected and the size being sent. The NDI and OMT guide has the
setup in each mixer: [NDI and OMT](/docs/other-software/ndi-and-omt).

## The splash screen in streams

While there's no video, the streams carry the
[splash screen](/docs/using/splash-and-logo), so players stay connected and pick the
video back up when it returns.
